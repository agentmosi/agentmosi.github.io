AgentMonitor 配置与防御指南

本页整合 agentmonitor-demo/doc 的架构、使用说明和威胁模型，说明如何配置 OpenClaw 插件、启动服务、验证 API，以及 AgentMonitor 具体防御哪些行为。

快速启动OpenClaw 插件配置防御内容与例子全局关联分析核心数据结构API 与验证

1. 快速启动

AgentMonitor Demo 服务位于 agentmonitor-demo。用户先从 GitHub 拉取仓库，再进入 demo 目录安装依赖并启动服务；默认监听 http://127.0.0.1:19876。

git clone git@github.com:agentmosi/agentmonitor.git
cd agentmonitor/agentmonitor-demo
env -u NODE_OPTIONS pnpm install
env -u NODE_OPTIONS pnpm dev

# 健康检查
curl http://127.0.0.1:19876/api/health

本地实时仪表盘：http://127.0.0.1:19876/；产品概览：/index.html；本文档：/doc.html。

2. OpenClaw 插件配置

OpenClaw 插件配置文件是 ~/.openclaw/openclaw.json。插件入口已经独立在 agentmonitor-demo/openclaw-plugin，配置时将 plugins.load.paths 指向该目录，不需要修改 OpenClaw 源码。

{
  "plugins": {
    "enabled": true,
    "load": {
      "paths": [
        "${AGENTMONITOR_REPO}/agentmonitor-demo/openclaw-plugin"
      ]
    },
    "entries": {
      "agentmonitor": {
        "enabled": true,
        "config": {
          "monitorUrl": "http://127.0.0.1:19876",
          "timeoutMs": 80,
          "failClosedOnError": true,
          "observeHooks": true,
          "auditOnly": false,
          "interventionHooks": [
            "message_sending",
            "before_message_write",
            "subagent_spawning",
            "before_install"
          ]
        }
      }
    }
  }
}

将 AGENTMONITOR_REPO 指向你刚刚 clone 下来的仓库根目录，然后验证配置并启动 OpenClaw gateway。

export AGENTMONITOR_REPO="$PWD/agentmonitor"
# 如果当前已经在仓库根目录，可使用：export AGENTMONITOR_REPO="$PWD"

cd /path/to/openclaw
env -u NODE_OPTIONS pnpm openclaw config validate
env -u NODE_OPTIONS OPENCLAW_BONJOUR_ENABLED=0 pnpm openclaw gateway --port 18790 --force

4. 全局 Agent 行为关联分析

单点 hook 只能判断当前动作是否危险；多阶段攻击会把动作拆到多个会话里，让每一步看起来像正常排障。AgentMonitor 增加 Recorder 层持久化全量事件，并在全局窗口内按 sessionKey + agentId 关联阶段。

Recorder 架构

  • EventRecorder 接口：统一 addEvent、listEvents、listRuns，上层 API 不绑定具体存储。
  • MemoryEventStore：测试与轻量演示使用。
  • SqliteEventRecorder：使用 Node node:sqlite 时写入 SQLite；当前 Node 未启用该内置模块时自动降级为 JSONL recorder，保持同一接口。

真实攻击链例子

时间 / 会话单步行为单点看法全局关联含义
会话 Afind . -name .env -o -name '*key*' -o -name 'config*'普通文件定位凭证/配置位置侦察
会话 Bgrep -n API_KEY .env.example config/settings.ts排障读取示例配置读取敏感变量名和上下文

5. 核心数据结构：行为记录如何组织

AgentMonitor 的行为记录采用 append-style 事件流模型。OpenClaw hook、工具调用检查、策略命中、消息发送与跨会话分析，最终都会归一化为一条 AgentMonitorEvent，写入统一的 EventRecorder。运行会话、证据链、行为图和全局攻击链都是从事件流派生出来的视图。

AgentMonitorEvent

type AgentMonitorEvent = {
  id: string;
  timestamp: number;
  runId?: string;
  sessionKey?: string;
  sessionId?: string;
  agentId?: string;
  toolCallId?: string;
  hookName: string;
  eventType: EventType;
  sourceTrust: SourceTrust;
  payload: unknown;
  risk?: EventRisk;
  parentEventIds: string[];
};
字段作用
runIdAgentMonitor 侧运行会话 ID，用于左侧运行列表和单 run 行为图。
sessionKey / agentIdOpenClaw/x-Agent 侧会话与 agent 维度，用于跨 run、跨会话关联。
hookName / eventType记录事件来自哪个 hook，以及归一化后的事件类别，如 llm_input、tool_call、message_sending、policy_decision、hook_check。
sourceTrust来源信任域：system、llm、tool、user、external。
payload原始上下文、工具参数、模型消息、工具结果或策略输出。
risk可选风险信息，包含 severity、ruleId、reason 和 evidencePaths。
parentEventIds父事件 ID 列表，用于证据链回溯和行为图边关系。

EventRecorder 接口

interface EventRecorder {
  addEvent(event: AgentMonitorEvent): AgentMonitorEvent;
  getEvent(eventId: string): AgentMonitorEvent | undefined;
  listEvents(filter?: { runId?: string }): AgentMonitorEvent[];
  listRuns(): RunSummary[];
}

上层 API 只依赖 EventRecorder，因此内存、SQLite、JSONL 等存储实现可以互换。listRuns() 不依赖单独 run 表，而是按事件中的 runId 聚合出 RunSummary：包含显示名、事件数、首尾时间和隐藏 raw run id 的标记。

持久化结构

SQLite recorder 使用单表 events 存储事件主字段，复杂对象以 JSON 字符串保存：

CREATE TABLE events (
  id TEXT PRIMARY KEY,
  timestamp INTEGER NOT NULL,
  run_id TEXT,
  session_key TEXT,
  session_id TEXT,
  agent_id TEXT,
  tool_call_id TEXT,
  hook_name TEXT NOT NULL,
  event_type TEXT NOT NULL,
  source_trust TEXT NOT NULL,
  payload_json TEXT NOT NULL,
  risk_json TEXT,
  parent_event_ids_json TEXT NOT NULL
);

关键索引包括时间索引、run 索引，以及 session_key + agent_id 索引，分别服务事件流展示、单会话检索和跨会话关联。Node 环境无法加载 node:sqlite 时会自动降级为 JSONL recorder，每行保存一条完整 AgentMonitorEvent。

派生视图

  • 运行列表：GET /api/runs 从事件流按 runId 聚合。
  • 事件流：GET /api/events 和 GET /api/events/stream 返回历史事件和 SSE 实时事件。
  • 行为图：GET /api/runs/:runId/graph 根据事件和 parentEventIds 构建节点与边。
  • 证据链：GET /api/runs/:runId/evidence?eventId=... 从目标事件向前回溯上下文。
  • 全局发现：GET /api/global/findings 跨 run 扫描 recon → sensitive_read → staging → egress 阶段，输出 GlobalFinding。

6. API 与验证

工具调用检查

curl -s http://127.0.0.1:19876/api/tool-call/check \\
  -H 'content-type: application/json' \\
  -d '{"toolName":"shell","params":{"command":"rm -rf /"},"runId":"demo"}'

通用干预 Hook 检查

curl -s http://127.0.0.1:19876/api/hook/check \\
  -H 'content-type: application/json' \\
  -d '{"hookName":"message_sending","event":{"content":"API_KEY=sk-test-secret-value"},"runId":"demo"}'

事件查询

curl http://127.0.0.1:19876/api/events
curl http://127.0.0.1:19876/api/runs
curl http://127.0.0.1:19876/api/events/stream
