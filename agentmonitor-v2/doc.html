AgentMonitor 细节、配置指南与监控粒度

本页说明如何把 AgentMonitor 接入本地 Agent runtime、如何验证 API，以及内部核心数据结构如何支撑实时监控、证据链、敏感数据流向和跨会话攻击链分析。

快速启动配置指南核心数据结构监控粒度API 与验证

1. 快速启动

AgentMonitor Demo 默认监听 http://127.0.0.1:19876。根路径 / 和 /index.html 是实时监控台，/info.html 是框架概括，/doc.html 是本文档。

git clone git@github.com:agentmosi/agentmonitor.git
cd agentmonitor/agentmonitor-demo
env -u NODE_OPTIONS pnpm install
AGENTMONITOR_ENABLED=1 AGENTMONITOR_URL=http://127.0.0.1:19876 env -u NODE_OPTIONS pnpm dev

curl http://127.0.0.1:19876/api/health

2. 配置指南

OpenClaw 插件入口位于 agentmonitor-demo/openclaw-plugin。配置时使用 plugins.load.paths 指向该目录，并把 monitor URL 指向本地服务。

{
  "plugins": {
    "enabled": true,
    "load": {
      "paths": [
        "${AGENTMONITOR_REPO}/agentmonitor-demo/openclaw-plugin"
      ]
    },
    "entries": {
      "agentmonitor": {
        "enabled": true,
        "config": {
          "monitorUrl": "http://127.0.0.1:19876",
          "timeoutMs": 80,
          "failClosedOnError": true,
          "observeHooks": true,
          "auditOnly": false,
          "interventionHooks": [
            "message_sending",
            "before_message_write",
            "subagent_spawning",
            "before_install"
          ]
        }
      }
    }
  }
}

Adapter 型 runtime 可以直接投递统一事件：

curl -s http://127.0.0.1:19876/api/adapters/openclaw/events \
  -H 'content-type: application/json' \
  -d '{"hookName":"chat.tool_call","payload":{"toolName":"shell","command":"cat .env"},"runId":"demo"}'

3. 核心数据结构

所有运行时事件会归一化为 AgentMonitorEvent，再写入 EventRecorder。该模型既能承载实时 UI，也能承载持久审计和跨会话关联。

type AgentMonitorEvent = {
  id: string;
  timestamp: number;
  runId?: string;
  sessionKey?: string;
  sessionId?: string;
  agentId?: string;
  toolCallId?: string;
  hookName: string;
  eventType: EventType;
  sourceTrust: SourceTrust;
  payload: unknown;
  risk?: EventRisk;
  parentEventIds: string[];
};

interface EventRecorder {
  addEvent(event: AgentMonitorEvent): AgentMonitorEvent;
  getEvent(eventId: string): AgentMonitorEvent | undefined;
  listEvents(filter?: { runId?: string }): AgentMonitorEvent[];
  listRuns(): RunSummary[];
}
字段用途
runId监控台左侧运行会话、单 run 事件筛选、行为树构建。
sessionKey / agentId跨 run 关联同一 agent 或同一业务会话，发现多阶段攻击链。
hookName保存原始 runtime hook，如 chat.tool_call、message_sending、after_tool_call。
eventType归一化类别，如 llm_input、tool_call、tool_result、policy_decision。
sourceTrust标记来源信任域：system、llm、tool、user、external。
parentEventIds构建证据链和行为图边关系，解释某次阻断依赖哪些上游事件。

4. 监控粒度

AgentMonitor 采用“高价值状态转移优先”的粒度：默认采集决策点、工具边界和最终消息，不默认采集高频 token 流，避免实时监控被噪声淹没。

粒度事件示例默认策略说明
LLM 边界llm_input、llm_output、chat.final采集用于理解模型收到什么、最终输出什么。
工具边界tool_call、tool_result、chat.tool_call采集并可阻断最关键的副作用边界，支持命令、文件、网络和安装检查。
消息外发message_sending、before_message_write采集并可阻断用于防止 token、private key、API key 出站或持久化。
策略决策policy_decision、hook_check采集记录 block、allow、requireApproval 与规则命中原因。
Token 流chat.delta默认不采集 chat.delta仅在调试模式启用，防止吞吐和存储压力过高。
